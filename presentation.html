Without OPM (Traditional Approach)
• Hardcoded scripts: Every policy check requires custom Python and redeploys.
• Model amnesia: Models forget rules between sessions, violating standards.
• Prompt bloat: 30-page SOPs dumped into every request trigger hallucinations.
With OPM Process Memory
• Zero-code updates: Leads define enforceable rules in plain English.
• Quarantine immunity: 0 unapproved rules reach model prompts or ERP.
• Minimal token overhead: Injects only relevant rules (~80 tokens vs 4,000+).
Key Outcome: Business policies stay in company memory, not in custom code. Developers never modify gateway services for operational policy changes.

Zero-Trust Gateway

Decoupled Gateway & Zero-Trust Dispatch

Protecting core ERP databases from unconstrained AI access without hardcoding business workflows.

ENCRYPTED EXECUTION PIPELINE COGNITO ➔ BEDROCK ➔ ODOO 17
Credentials masked in traces Schema-validated dispatch
1. Pure Gateway Decoupling

OPM contains zero hardcoded Odoo task recipes, Gantt formulas, or status workflows. It acts purely as a protocol and policy router.

• Standard FastMCP tool contracts • Decoupled from ERP API shifts
2. Cryptographic Multi-Tenancy

Tenant and user identity is resolved cryptographically from Cognito JWTs. Client applications cannot spoof company IDs or roles.

• Zero client-controlled identity • Owner/reviewer role enforcement
3. Credential Masking & Audit Trace

Downstream ERP passwords are resolved via AWS Secrets Manager and masked from logs. Unsafe raw endpoints like execute_kw are blocked.

• Model never sees credentials • 100% deterministic trace telemetry
